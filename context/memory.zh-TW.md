# DeskGrid 記憶體：用在哪裡、怎樣維持低用量

> 這份檔案與 `memory.md` 是雙胞胎（英文 / 繁體中文）：兩份要一起修改。

## 數據（2026-11-23 實測，Windows 11，已發佈的 exe，NotiLand 開啟，8 個資料夾）

| | 之前 | 之後 |
|---|---|---|
| 私有記憶體，閒置 | 195 MB | 129 MB |
| 私有記憶體，剛關掉面板 | 231 MB | 141 MB |
| 啟動時的工作集（尖峰） | 375 MB | 245 MB |
| 工作集，閒置 | 51-62 MB | 16-55 MB |
| 工作集，開關面板後 2 秒 | 139-147 MB，好幾分鐘不退 | 123 MB，27 秒後 16 MB |
| 點工作列按鈕到面板像素出現 | 51-66 ms | 56-70 ms（相同） |

使用者能做的事完全沒有改變：`context/memory.md` 只談程式怎樣持有記憶體。唯一的代價是 exe 變大（約 189 MB，原本 83 MB）。

## 記憶體在哪裡

- **.NET 堆積很小**（清理後 9-17 MB）。不要先從這裡找節省。
- **私有記憶體**（閒置約 125 MB）大多是原生的：執行階段、JIT 程式碼、WPF 與 Direct3D 自己的堆積，以及圖片。
- **壓縮的單檔套件在程式啟動時會被解開放進私有記憶體**，每一個組件都是（自包含的框架帶來約 190 MB）。那就是 68 MB 的私有記憶體、啟動時 130 MB 的工作集，以及每次啟動約 130 ms。
- **開過的面板約佔 90 MB 工作集**（渲染器、玻璃圖片、它執行過的程式碼），而且自己不會還回去。
- **每開一個面板沒有洩漏**：開關 40 次、再清理之後，比開始時只多 7 MB，控制代碼數也回到原來的數字。

## 維持低用量的做法（不要拆掉）

1. **單檔 exe 不壓縮**（`Properties/PublishProfiles/win-x64.pubxml` 裡 `EnableCompressionInSingleFile` 是 `false`）。組件是從 exe 映射進來的，只讀會執行到的部分。再開啟壓縮會多花約 68 MB 私有記憶體，每次啟動多 130 ms。如果之後下載大小比較重要，請改成精簡套件裡的內容（用不到的框架組件），並重新量測。
2. **閒置清理**（`Diagnostics/MemoryTrim`，由 `App.RequestMemoryTrim` 要求）：任何一次使用（面板關閉、設定關閉、啟動）之後 20 秒，壓縮堆積、把用不到的還給 Windows，並讓程序的分頁離開工作集。面板開著、NotiLand 使用中（`NotiLandHost.InUse`）、設定視窗開著、滑鼠按鍵按著（拖曳）時，它會等。再用到的會一頁一頁回來：清理後的第一個面板跟其他的一樣快（57-65 ms，對照暖機時的 56-70 ms）。
3. **桌面圖示用軟體繪製**（桌面 surface 與隱藏的訊息視窗設 `RenderMode = SoftwareOnly`），所以第一次開面板之前沒有 Direct3D 裝置（見 `CLAUDE.md`「DesktopHost notes」）。
4. **快取的圖片跟著資料夾走**：`IconService.Retain` 在每次更新時丟掉消失或變動的；面板只在開著的時候持有玻璃用的畫面圖片（`PanelGlass`），而且只擷取面板四周（`CaptureMargin`），不是整個工作區。
5. **NotiLand 保有自己較長的清理**（BrimDeck 的 `MemoryMode`，預設「Balanced」）；上面的閒置清理是宿主的，不取代它。

## 修改時的規則

- 修改不能拿掉功能，也不能讓點擊變慢。照下面的方法，改前改後都要量。
- 面板關閉後，不要繼續持有它建立的視窗、點陣圖或工作。不要快取讀一次很便宜的東西。
- 新的背景計時器或監看器，只要 DeskGrid 在執行就是一條執行緒、一個控制代碼和一些記憶體：沒東西要等的時候要讓它停下來。
- 新的套件或新的框架參考會讓套件變大；套件是映射的、不是解開的，所以只有會執行到的部分才佔工作集，但它會增加下載大小。

## 怎樣量

目前只在一台電腦、一個螢幕、一種縮放比例上量過；多螢幕與其他縮放比例沒量（玻璃用的圖片與格子尺寸會受影響）。要在那些環境依賴這些數字之前，先量一次。

1. 用真正執行的方式啟動已發佈的版本（`tools/run-latest.ps1`，或 `explorer.exe DeskGrid.exe`），等 20 秒再等 60 秒。
2. `DeskGrid.exe --ctl memory`（需要開啟「允許腳本與 AI agent 控制」）會給出受控堆積、垃圾回收器持有的量、工作集與私有記憶體。工作管理員的「記憶體」是私有工作集，比兩者都小。
3. 開關一個面板（`--ctl open Dev`、`--ctl close`），在 2 秒與 30 秒時各讀一次：工作集必須自己降回去。
4. 開關面板 40 次，等清理後再讀：私有記憶體必須回到接近開始時的數字，控制代碼數（`Get-Process DeskGrid`）也一樣。
5. 當私有記憶體長大、堆積卻沒有時，用 `VirtualQueryEx` 檢查程序各區域持有什麼（私有、映射與映像記憶體）：堆積很小，所以成長就是原生的。
6. 檢查功能（做過什麼列在 `context/decisions.md`，2026-11-23（六））：每個資料夾的面板、所有資料夾的列表、真的點釘選的工作列按鈕與桌面資料夾、建立／加入項目／改名／刪除資料夾、NotiLand 的視窗，以及記錄檔有沒有錯誤。再量速度：從真實點擊到面板第一批像素的時間，暖機時與清理之後各量。
